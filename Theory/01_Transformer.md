# 1단계: Transformer 아키텍처

---

## 먼저, AI가 텍스트를 어떻게 이해할까?

컴퓨터는 글자를 직접 이해 못합니다. 모든 걸 **숫자**로 바꿔야 해요.

```
"나는 밥을 먹었다"
        ↓
[1042, 8, 231, 9, 5523]  ← 토큰(Token)으로 변환
```

이렇게 단어(또는 단어 조각)를 숫자로 바꾼 걸 **토큰**이라고 합니다.

---

## 핵심 문제: 단어 순서와 문맥

> "나는 **배**가 고프다" vs "항구에 **배**가 있다"

같은 "배"지만 의미가 완전히 다릅니다.
Transformer 이전 모델들은 이걸 잘 구분 못했어요.

Transformer는 이 문제를 **Attention(주의집중)** 으로 해결합니다.

---

## Attention이란?

> "이 단어를 해석할 때, 문장의 어느 부분에 집중해야 하는가?"

```
"The animal didn't cross the street because it was too tired"

"it"이 무엇을 가리키는가?
  → "animal" 에 높은 attention
  → "street" 에 낮은 attention
```

사람이 글을 읽을 때 문맥을 파악하는 것과 같은 원리입니다.

---

## Transformer 전체 구조 (간단 버전)

```
입력 텍스트
    ↓
[토크나이저] - 텍스트를 숫자로 변환
    ↓
[임베딩]    - 숫자를 벡터(다차원 좌표)로 변환
    ↓
[Self-Attention] - 단어들끼리 서로 얼마나 관련있는지 계산
    ↓
[Feed Forward] - 패턴 학습
    ↓
(위 2개를 N번 반복 ← 이게 "레이어(Layer)")
    ↓
출력
```

GPT-4는 이 레이어가 수백 개입니다. 깊을수록 더 복잡한 문맥 이해 가능.

---

## Self-Attention 직관적으로 이해하기

각 단어가 다른 모든 단어에게 "너 나랑 얼마나 관련있어?" 라고 물어보는 과정입니다.

```
문장: "고양이가 생선을 먹었다"

"먹었다" 입장에서:
  고양이가 → 관련도 0.6  (먹은 주체)
  생선을   → 관련도 0.8  (먹은 대상)
  먹었다   → 관련도 0.1  (자기 자신)
```

이 관련도(가중치)를 계산하는 게 **Attention Score** 입니다.

---

## LLM이 텍스트를 생성하는 원리

LLM은 **"다음 토큰 예측"** 게임을 합니다.

```
입력: "오늘 날씨가"
  → 다음 토큰 후보: ["좋다"(45%), "나쁘다"(30%), "흐리다"(20%), ...]
  → "좋다" 선택

입력: "오늘 날씨가 좋다"
  → 다음 토큰 후보: ["서"(40%), "!"(35%), ","(20%), ...]
  → "서" 선택

... 반복
```

이 예측을 수조 개의 텍스트 데이터로 학습한 결과가 GPT, Claude 같은 LLM입니다.

---

## 정리

| 개념 | 한줄 요약 |
|------|-----------|
| 토큰 | 텍스트를 숫자로 쪼갠 단위 |
| 임베딩 | 토큰을 의미있는 벡터로 변환 |
| Attention | 단어 간 관련도 계산 |
| Self-Attention | 문장 내 모든 단어가 서로 관련도 계산 |
| LLM | 다음 토큰 예측을 반복해서 텍스트 생성 |
